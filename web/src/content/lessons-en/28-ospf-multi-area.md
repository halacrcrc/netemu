Single-area OSPF creates two problems at scale: every topology change triggers a full recomputation, and the LSDB grows without bound. **Multi-area OSPF** groups routers so each area computes internally while only summary routes cross area boundaries.

## Area roles

- **Backbone area 0**: every area must connect to it, and inter-area routes transit through it;
- **ABR (Area Border Router)**: connects area 0 to other areas and generates Type-3 summary LSAs;
- **ASBR (AS Boundary Router)**: redistributes external routes as Type-5 LSAs (Type-7 inside an NSSA).

```
Area type      Characteristics
Normal         Accepts Type-3/4/5
Stub           Rejects Type-4/5, uses a default route out
Totally Stub   Keeps only a default route, further reduced
NSSA           Allows external routes (Type-7), rejects Type-5
```

## LSA quick reference

```
Type 1  Router LSA        Flooded by every router inside the area
Type 2  Network LSA       Generated by the DR, describes a broadcast segment
Type 3  Summary LSA       Generated by ABRs for inter-area prefixes
Type 4  ASBR Summary      An ABR tells other areas where the ASBR is
Type 5  External LSA      External routes redistributed by an ASBR
Type 7  NSSA External     External routes inside an NSSA
```

## Convergence and optimization

- **SPF throttling**: limit SPF runs so flapping does not spike CPU;
- **PRC (partial route calculation)**: skip the full tree when only leaf nodes change;
- **BFD**: detect neighbor failure in milliseconds instead of waiting for Hello timeouts;
- **LSA summarization**: ABRs use `area range` to aggregate details and shrink the LSDB;
- **Stub/NSSA**: suppress unnecessary external flooding.

## Verification

```
display ospf peer          show ip ospf neighbor
display ospf lsdb          show ip ospf database
display ospf routing       show ip ospf route
```

Troubleshoot neighbor state first (Down/Init/2-Way/ExStart/Exchange/Loading/Full), then LSDB consistency, then route selection.
