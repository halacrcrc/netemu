所有网络技术都建立在同一套分层模型上。理解"数据从应用到网线要经过哪些层、每层加什么头"，后面的 VLAN、路由、NAT 才不会变成死记命令。

## 两个模型，一张地图

OSI 七层是教学模型，TCP/IP 四/五层是工程模型：

```
OSI                      TCP/IP              典型协议 / 设备
应用 / 表示 / 会话       应用层               HTTP、DNS、SSH
传输层                   传输层               TCP、UDP
网络层                   网络层               IP、ICMP、ARP（常归二层）
数据链路层               网络接口层            Ethernet、PPP、VLAN
物理层                                       双绞线、光纤、无线
```

- **交换机**看二层 MAC 头，**路由器**看三层 IP 头；
- 每一层只关心对等层的头部，下层为上层提供服务；
- 封装自上而下加头，解封装自下而上剥头。

## 一次 ping 到底发生了什么

1. 应用层生成 ICMP Echo 请求；
2. 网络层加 IP 头，查路由表决定出接口与下一跳；
3. 若下一跳 MAC 未知，先用 **ARP** 广播询问"谁拥有这个 IP"；
4. 数据链路层加以太网头，从接口发出；
5. 沿途路由器逐跳减 **TTL**，到 0 丢弃并回 ICMP 超时；
6. 目的主机回 Echo Reply，路径对称或按路由返回。

ARP 只在**同一广播域**内工作——这也是"跨网段 ping 不通先查网关/ARP"的原因。TCP 提供面向连接的可靠传输（三次握手、序号确认、重传），UDP 无连接、开销小，适合 DNS、语音、视频。

## 在本模拟器里

打开任意设备终端执行：

```
ping 192.168.1.1
show ip interface brief
show ip route
```

抓包可以看到每一层的头部：以太网 MAC、IP 地址与 TTL、ICMP 类型。把 TTL 的变化和路由跳数对上，是理解逐包转发最快的方式。

## 动手

打开实验一：两台交换机同 VLAN 的 PC 能通，是因为 ARP 广播被泛洪到同一广播域；跨 VLAN 不通，则是二层隔离。再打开实验二的 SVI，观察跨 VLAN 通信时 TTL 减 1——说明报文真的经过了一次三层转发。
