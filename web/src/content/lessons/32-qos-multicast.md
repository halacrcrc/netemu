网络拥塞时，所有流量"公平"地一起丢，语音会卡、视频会花。**QoS** 给不同业务不同待遇；**组播**则让一份流量同时送达多个接收者，避免源端重复复制。

## QoS 的四个动作

```
分类（Classification）  按 ACL、端口、DSCP 识别业务
标记（Marking）         打 DSCP/CoS，后续设备直接信任
 policing（监管）        超速直接丢弃或降级，守住承诺速率
 shaping（整形）         超速先缓存，平滑发送，增加延迟
排队（Queuing）         PQ 优先、WFQ 公平、LLQ 低延迟队列
```

DSCP 占 IP 头 6 位（0~63）：**EF=46** 常用于语音，**AF41=34** 用于视频，**CS6/CS7** 留给协议控制。端到端 QoS 要求每一跳都信任并执行同一套标记，否则标记会在边界被清掉。

拥塞避免常用 **WRED**：队列快满时按概率提前丢弃低优先级报文，避免全网同步丢包（TCP 全局同步）。

## 组播：一份流量，多个接收者

- **IGMP**：主机告诉路由器"我要加入哪个组"（IGMPv2/v3）；
- **PIM-SM**：稀疏模式，先建共享树（RP 为根，`(*,G)`），流量大了再切换到源树（`(S,G)`）；
- **PIM-SSM**：直接指定源与组，适合视频/直播；
- **RPF 检查**：组播报文必须从"去往源的最短路径接口"进来，否则丢弃——这是组播防环的核心。

组播地址 `224.0.0.0/4`，其中 `224.0.0.0/24` 是链路本地协议地址；`239.0.0.0/8` 留作私有组播。

## 在本模拟器里

模拟器实现了**广播风暴抑制**与**入方向限速**，可以看到丢弃/抑制计数：

```
思科：
storm-control broadcast level 100
rate-limit input 1000
华为/华三：
broadcast-suppression 100
qos car inbound cir 1000
```

完整的 DSCP 队列、WRED、PIM 未建模，但可以用"先分类、再标记、最后排队/丢弃"的框架理解真实设备的行为。

## 动手

打开实验九：给接入端口配置广播抑制，制造广播流量观察丢弃计数；再给上联口配置限速，观察超过承诺速率的流量被丢弃。思考：为什么语音流量更适合 LLQ，而大文件下载更适合 WFQ？
