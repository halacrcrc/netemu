为了可靠性，交换机之间往往拉两条链路——但二层没有 TTL，广播帧会在环路里无限复制，形成**广播风暴**。STP（生成树协议）的逻辑上阻塞冗余端口，把有环的物理拓扑剪成无环的树。

## 三个角色

- **根桥（Root Bridge）**：全网的大脑，比较桥 ID（优先级 + MAC，越小越优）选出。
- **根端口（RP）**：每台非根桥上，去往根桥成本最低的端口。
- **指定端口（DP）**：每条链路上，负责转发的端口。
- 落选的端口成为**替换端口（Alternate）**，被阻塞。

## 状态机与收敛时间

端口不是一上来就转发，而是：

```
Blocking → Listening → Learning → Forwarding
           └─ 15s ─┘ └─ 15s ─┘
```

邻居失联 20 秒（Max Age）后才认为它死了——所以经典 STP 故障收敛要 30~50 秒。**改根桥后全网端口要重新走一遍状态机**，这不是 bug，是 802.1D 的真实节奏。

## 广播风暴长什么样

在本模拟器里把两台交换机都 `stp disable`，再 ping 一次：广播帧在环路里指数复制，状态栏的"丢弃"数瞬间飙升。这就是为什么环路拓扑绝不能关 STP。
