Segment Routing 把路径编码进报文：源节点决定经过哪些段，中间节点只按段标识转发。**SRv6** 用 IPv6 地址作为段标识（SID），不再依赖 MPLS 标签，天然适合云网与可编程承载。

## 三个核心概念

- **Locator**：一段 IPv6 前缀，标识 SRv6 域内的节点/位置；
- **SID**：Locator 内的具体段标识，如 `2001:db8:100::1`；常见行为 `End`、`End.DX6`；
- **Segment List**：源端写入的 SID 序列，对应一条显式路径。

**BE（Best Effort）** 只指定一个远端 SID：入口把原始报文封装成外层 IPv6（目的=SID），Underlay 按普通 IPv6 路由转发，出口识别本地 SID 后解封装交付。**Policy** 则用 Segment List 指定多段路径，支持流量工程与切片。

## 本模拟器的 SRv6 BE

```
srv6 locator 2001:db8:100::/64
srv6 sid 2001:db8:100::1
srv6 route 2001:db8:2::/64 sid 2001:db8:200::1
```

- 入口匹配 `srv6 route` 的业务前缀，封装外层 IPv6（目的为远端 SID）；
- Underlay 用 IPv6 静态/OSPFv3 路由把外层送到对端；
- 对端发现目的 SID 属于本地 locator/SID，解封装后按内层 IPv6 转发。

查看：`display srv6` / `show srv6`。抓包能看到外层 IPv6 的源/目的是 Locator/SID，内层才是 PC 之间的原始 ICMPv6。

## 与 MPLS/SR-MPLS 的关系

- **SR-MPLS**：SID 是 MPLS 标签，需要标签栈；
- **SRv6**：SID 是 IPv6 地址，可编程性更强，支持网络切片、业务链；
- **TI-LFA**：SR 的拓扑无关无环备份，故障亚秒切换；
- **演进**：现有 MPLS VPN 可逐步与 SRv6 共存，出口/入口分别封装。

## 动手

打开实验二十二：配置 R1/R2 的 Locator、本地 SID、业务网段 SRv6 路由与 Underlay 静态路由。`display srv6` 应看到路由与 SID；PC1 ping6 PC2 应通。再把 R1 的 `srv6 route` 改成错误 SID，观察业务如何中断。
